A small update to 1.0.0: once the payload has gone to the console, the Pico now tidies up after the injection.

**What changed:**
- **The boot counters stop** once the boot's counts are read. In 1.0.0 they kept counting CS pulses until power-off. The Diagnostics tab shows the same counts as before.
- **The bus priority** that the injection's DMA needs goes back to normal.
- **The data line's input is turned off** once the Pico has released the line. On RP2350 A2 chips, erratum E9 could otherwise hold the floating line at about 2.2 V.

None of these caused a known problem in 1.0.0. The payloads, the settings, the page and the command-line tool are unchanged.

**Updating from 1.0.0:** install `picoboot-wifi-1.0.1-update.bin` on the Firmware tab, or with `python3 picoboot-wifi.py update picoboot-wifi-1.0.1-update.bin`. It starts on trial, and it keeps itself after the next power-on that boots the console. A first install or a recovery uses the UF2, as the [README](https://github.com/r3mko/PicoBoot-WiFi#readme) describes.

**Files:**

| File | What it is |
|---|---|
| `picoboot-wifi-1.0.1.uf2` | The USB install: a first install, an upgrade from PicoBoot-DX, or a recovery. Copy it onto the Pico's drive (hold BOOTSEL while connecting USB). It leaves the payloads in place |
| `picoboot-wifi-1.0.1-update.bin` | The update over Wi-Fi from 1.0.0 (the Firmware tab, or the CLI's `update`) |
| `picoboot-wifi.py` | The command-line tool (Python 3, standard library only), the same as in 1.0.0 |
| `SHA256SUMS` | The SHA-256 of each file |

**Notes:** as for 1.0.0. Change the default Wi-Fi password (`picoboot`). Tested on a DOL-001.
