A small update to 1.0.1: when the data to write to flash is itself in flash, the Pico now copies it into RAM first.

**What changed:**
- **Writes from flash are copied through RAM.** Flash can't be read while it's being written, so a write whose data is in flash would hang the Pico until its watchdog reset it. This happened to payload uploads while 1.0.0 was being tested, and was fixed then by moving that one piece of data into RAM. Now the Pico copies such data into RAM first, a page at a time, so it can't happen again.
- **Payload uploads and deletes use the copy.** Before it erases a payload slot, the Pico writes zeros over the slot's first page. Those zeros are in flash again, so every upload and delete goes through the copy.

Every other write already came from RAM and works as in 1.0.1. The payloads, the settings, the page and the command-line tool are unchanged.

**Updating from 1.0.1 or 1.0.0:** install `picoboot-wifi-1.0.2-update.bin` on the Firmware tab, or with `python3 picoboot-wifi.py update picoboot-wifi-1.0.2-update.bin`. It starts on trial, and it keeps itself after the next power-on that boots the console. A first install or a recovery uses the UF2, as the [README](https://github.com/r3mko/PicoBoot-WiFi#readme) describes.

**Files:**

| File | What it is |
|---|---|
| `picoboot-wifi-1.0.2.uf2` | The USB install: a first install, an upgrade from PicoBoot-DX, or a recovery. Copy it onto the Pico's drive (hold BOOTSEL while connecting USB). It leaves the payloads in place |
| `picoboot-wifi-1.0.2-update.bin` | The update over Wi-Fi from 1.0.1 or 1.0.0 (the Firmware tab, or the CLI's `update`) |
| `picoboot-wifi.py` | The command-line tool (Python 3, standard library only), the same as in 1.0.0 |
| `SHA256SUMS` | The SHA-256 of each file |

**Notes:** as for 1.0.0. Change the default Wi-Fi password (`picoboot`). Tested on a DOL-001.
