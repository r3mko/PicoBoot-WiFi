A second way to find the payload's start, for noise on CS, and a firmer hold on the payload with either one.

**What's new:**
- **Length-based injection, a choice on the Payloads tab.**
  - **The standard injection** counts the console's 224 start-up reads of the IPL chip before it sends the payload. A blip on CS among them throws the count off, and the console starts its own menu.
  - **Length-based** finds the payload's first block by its length instead: the first read that's longer than a start-up read. Such blips don't matter to it.
  - **Standard stays the default.** Both boot on clean wiring. Length-based is untested on noisy wiring, and a glitch on CLK during those reads starts its payload too early. The README's Wiring section says when to try it.
  - **If a length-based boot fails,** Wi-Fi comes up as always: choose standard again. The command-line tool has `injection standard|length` too.
- **A firmer hold on the payload, with either method.** A blip on CS in the middle of one of the payload's blocks used to make every later block one bit late. Now each block waits for the console to end the one before.
- **The diagnostics show the method.** "This boot" names it, and the boot log marks length-based boots. Entries logged before the update read as standard.

**What stays:**
- Your payloads, their choice and the settings stay as they are.
- The method is kept next to the payload choice, so updates keep it. A USB install sets it back to standard, as it resets the payload choice. An older firmware in the other slot ignores it and injects the standard way.

**Updating from 1.1.x or 1.0.x:** install `picoboot-wifi-1.2.0-update.bin` on the Firmware tab, or with `python3 picoboot-wifi.py update picoboot-wifi-1.2.0-update.bin`. It starts on trial, and it keeps itself after the next power-on that boots the console. A first install or a recovery uses the UF2, as the [README](https://github.com/r3mko/PicoBoot-WiFi#readme) describes. Replace your copy of `picoboot-wifi.py` for its `injection` command.

**Files:**

| File | What it is |
|---|---|
| `picoboot-wifi-1.2.0.uf2` | The USB install: a first install, an upgrade from PicoBoot-DX, or a recovery. Copy it onto the Pico's drive (hold BOOTSEL while connecting USB). It leaves the payloads in place |
| `picoboot-wifi-1.2.0-update.bin` | The update over Wi-Fi from 1.1.x or 1.0.x (the Firmware tab, or the CLI's `update`) |
| `picoboot-wifi.py` | The command-line tool (Python 3, standard library only), with the new `injection` command |
| `SHA256SUMS` | The SHA-256 of each file |

**Notes:** as for 1.0.0, except for `.dol` files (see 1.1.0). Change the default Wi-Fi password (`picoboot`). Tested on two DOL-001s.
