A firmer hold on the payload when noise comes between its blocks.

**What changed:**
- **Noise between the payload's blocks no longer throws the rest off, with either injection method.**
  - **Before:** a glitch on CS between two of the payload's blocks, or a blip inside one, could leave PicoBoot-WiFi a step ahead of the console. A clock pulse while CS was high before a later block then counted as that block's start, and the rest of the payload came out of step.
  - **Now:** each block waits until the console has begun its transfer.
  - **Where it was found:** in the simulator, while bringing 1.2.0's change to PicoBoot-DX; it hasn't been seen on a console.
- **Still not covered:** a clock pulse right after such a glitch, before the next transfer starts.

The injection methods, your payloads, the settings and the command-line tool work as before.

**Updating from 1.2.0, 1.1.x or 1.0.x:** install `picoboot-wifi-1.2.1-update.bin` on the Firmware tab, or with `python3 picoboot-wifi.py update picoboot-wifi-1.2.1-update.bin`. It starts on trial, and it keeps itself after the next power-on that boots the console. A first install or a recovery uses the UF2, as the [README](https://github.com/r3mko/PicoBoot-WiFi#readme) describes.

**Files:**

| File | What it is |
|---|---|
| `picoboot-wifi-1.2.1.uf2` | The USB install: a first install, an upgrade from PicoBoot-DX, or a recovery. Copy it onto the Pico's drive (hold BOOTSEL while connecting USB). It leaves the payloads in place |
| `picoboot-wifi-1.2.1-update.bin` | The update over Wi-Fi from 1.2.0, 1.1.x or 1.0.x (the Firmware tab, or the CLI's `update`) |
| `picoboot-wifi.py` | The command-line tool (Python 3, standard library only), the same as in 1.2.0 |
| `SHA256SUMS` | The SHA-256 of each file |

**Notes:** as for 1.0.0, except for `.dol` files (see 1.1.0). Change the default Wi-Fi password (`picoboot`). Tested on a DOL-001.
