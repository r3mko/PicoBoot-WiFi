A firmer hold on the payload when there's noise on CS.

**What changed:**
- **Noise between the payload's blocks no longer throws the rest off, with either injection method.**
  - **Before:** a glitch on CS between two of the payload's blocks, or a blip inside one, could leave PicoBoot-WiFi a step ahead of the console. A clock pulse while CS was high before a later block then counted as that block's start, and the rest of the payload came out of step.
  - **Now:** each block waits until the console has begun its transfer.
- **The payload's last bit is held to the end.** A blip on CS just before the payload's last clock could make PicoBoot-WiFi let go of the data line before the console read the last bit. It now waits for that clock first.
- **Length-based: the first block isn't missed after a glitch.** A glitch on CS that ended just before the payload's first block could make the length method wait through that block and start a block late.
- **Where they were found:** in the simulator, while bringing 1.2.0's change to PicoBoot-DX and in this release's code review. None has been seen on a console.
- **Still not covered:**
  - a clock pulse right after such a glitch, before the next transfer starts;
  - a clock pulse after a blip at the very end of a block.

The injection methods, your payloads, the settings and the command-line tool work as before.

**Updating from 1.2.0, 1.1.x or 1.0.x:**
- **The update:** install `picoboot-wifi-1.2.1-update.bin` on the Firmware tab, or with `python3 picoboot-wifi.py update picoboot-wifi-1.2.1-update.bin`. It starts on trial, and it keeps itself after the next power-on that boots the console.
- **The command-line tool:** from 1.1.x or 1.0.x, replace your copy of `picoboot-wifi.py` too, for its `injection` command, new in 1.2.0.
- **A first install or a recovery** uses the UF2, as the [README](https://github.com/r3mko/PicoBoot-WiFi#readme) describes.

**Files:**

| File | What it is |
|---|---|
| `picoboot-wifi-1.2.1.uf2` | The USB install: a first install, an upgrade from PicoBoot-DX, or a recovery. Copy it onto the Pico's drive (hold BOOTSEL while connecting USB). It leaves the payloads in place |
| `picoboot-wifi-1.2.1-update.bin` | The update over Wi-Fi from 1.2.0, 1.1.x or 1.0.x (the Firmware tab, or the CLI's `update`) |
| `picoboot-wifi.py` | The command-line tool (Python 3, standard library only), the same as in 1.2.0 |
| `SHA256SUMS` | The SHA-256 of each file |
